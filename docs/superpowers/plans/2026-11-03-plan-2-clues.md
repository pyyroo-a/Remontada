# Plan 2: Clues and the decoder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-frame evidence (touches, control, dead-ball clues, Smart Tagging hints) decoded by an HMM with Viterbi into H/A/D, plugged into `make_submission` and the scoreboard, and scored on IDSSE against the official baseline at every messiness level.

**Architecture:** New small modules under `src/remontada/`: `motion` (speeds from positions), `touch` (who has it), `dead_ball` (is play stopped), `smart_tagging` (loader), `evidence` (a count table learned on IDSSE that turns clues into per-frame scores), `hints` (fixed-rule hints: ball dead clues and Smart Tagging), `hmm` (Viterbi), `pipeline` (glue plus settings). Per-frame scores are always an `(n, 3)` float array with columns in label-code order H, A, D. `degrade.py` gets a slow-drift wobble and DATA.md-style ball hiding first, and the baseline is re-scored on it.

**Tech Stack:** Python 3.11, numpy 2.4.6, pandas 3.1.0, pytest 8.4.2. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-30-possession-pipeline-design.md` (approved 30 Oct 2026), sections 5.2 to 5.4 and 5.7. This is plan 2 of 3; plan 3 adds leave-one-match-out tuning of the settings, the explanations report, the final submission and the technical document.

## Decisions taken before this plan (3 Nov 2026, recorded in the vault hub)

1. **Slow-drift wobble (Ashen).** Position noise keeps its sizes (0.1, 0.25, 0.5 m) but drifts over about a second (AR(1), time constant 1.0 s) instead of jumping every frame. Measured on J03WMX: real median player speed 1.46 m/s; the old per-frame noise read as 10.6 m/s (medium) and 20.9 m/s (heavy) frame to frame.
2. **DATA.md-style hiding (Ashen).** Same hidden share per level; half of it starts on "hard" frames (ball in the air, `ball_z > 1.0`, or 3 or more players within 3 m of the ball, measured on the clean table), half uniform. DATA.md: "occlusions, crowded boxes and balls in the air all lose it".
3. **Speeds come from positions (Claude's call).** Same code for IDSSE and BAR-ATH; tracker speed fields are not read.
4. **Learn only honest parts of IDSSE (Ashen).** IDSSE freezes the ball for the whole of every dead stretch (309 of 309 in 3 matches). So the learned evidence covers only (a) who has the ball, from live frames, and (b) players slowing, from all frames. Ball dead clues (over the line, still, missing long) are fixed-rule hints, and the scoreboard reports with and without them.
5. **The written rule for hint weights (Claude's call, fixed before any score is seen).** Every hint (ball dead clues and Smart Tagging) adds the same per-frame weight `w` to its state's score: `w` is the median, over IDSSE live frames, of the absolute per-frame H-vs-A score difference of the learned team evidence. In words: a hint never counts for more than a typical tracking clue on one frame. Never tuned.
6. **Smart Tagging meanings come from the code names only (Claude's call).** No check on BAR-ATH frames. Attacking codes hint the tagged team; defending codes hint the other team; ambiguous codes and `N/A` give no hint (lists in Task 8).

### Task 4: Touch and control (who has it)

**Files:**
- Create: `src/remontada/touch.py`, `tests/test_touch.py`

**Interfaces:**
- Consumes: `motion.velocity`, `BALL_HALF_WINDOW` (Task 1).
- Produces:
  - `nearest_by_team(table) -> tuple[np.ndarray, np.ndarray]`: per frame, the distance from the ball to the nearest home and nearest away player; `inf` when that team has nobody visible; NaN when the ball is unseen.
  - `touches(table) -> np.ndarray[int8]`: team code at touch frames, -1 elsewhere. A touch is a frame where the ball is seen on `t-K`, `t`, `t+K` (`K = BALL_HALF_WINDOW`), `|v_after - v_before| >= TOUCH_DV` with `v_before = (b[t] - b[t-K]) * fps / K` and `v_after = (b[t+K] - b[t]) * fps / K`, it is the largest such change within `t-K..t+K`, and the nearest player is within `TOUCH_RADIUS`. The team is that player's team.
  - `control(table) -> np.ndarray[int8]`: team code on frames inside a run of at least `CONTROL_MIN_FRAMES` consecutive frames where the same team's nearest player is within `CONTROL_RADIUS` and nearer than the other team's nearest; -1 elsewhere.
  - `carry_forward(events: np.ndarray, max_age: int) -> np.ndarray[int8]`: the most recent non -1 value within the last `max_age` frames (inclusive), else -1.
  - Constants: `TOUCH_DV = 3.0` m/s, `TOUCH_RADIUS = 1.5` m, `CONTROL_RADIUS = 1.5` m, `CONTROL_MIN_FRAMES = 10` (0.4 s), `CARRY_FRAMES = 75` (3 s). Starting values; on J03WMX the nearest player is within 1 m on 40.7% of live frames and is the right team 93.3% of the time there (measured 3 Nov).

### Task 6: Viterbi decoder (teammate-friendly)

Mirrored swaps home and away in every part.
  - `slow_cells(table) -> np.ndarray[int16]`: players' median speed in bins `< 0.5 | 0.5..1.0 | 1.0..1.5 | 1.5..2.0 | 2.0..3.0 | >= 3.0 | unknown` m/s (7 cells).
  - `Counts` dataclass `(team: np.ndarray (54, 2), slow: np.ndarray (7, 2))`; `count(table, labels) -> Counts` (team: live frames only, H in column 0 and A in column 1, plus the mirrored cells with H and A swapped; slow: all labelled frames, column 0 live, column 1 dead; X frames ignored); `Counts.__add__`; `save_counts(counts, path)` and `load_counts(path)` as JSON (plain integer lists).
  - `emission_scores(table, counts, temperature) -> np.ndarray (n, 3)`: with additive smoothing of 1 per cell, `p_team[c, k] = P(cell c | k)` for `k` in H, A and `p_slow[c, j]` for `j` in live, dead. `score_H = temperature * (log p_team[c, H] + log p_slow[s, live])`, `score_A` likewise, `score_D = temperature * (log((p_team[c, H] + p_team[c, A]) / 2) + log p_slow[s, dead])`. So team clues never push towards or against D (decision 4).
  - `hint_weight(counts, temperature) -> float`: decision 5, computed from the table: the count-weighted median over team cells of `temperature * |log p_team[c, H] - log p_team[c, A]|`.
