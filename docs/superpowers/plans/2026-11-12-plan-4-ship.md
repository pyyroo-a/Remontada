# Plan 4: ship the Remontada submission, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a reproducible public repo, a short technical document (`remontada.pdf`) and a validated `remontada.csv`, ready to submit on 14 Nov 2026.

**Architecture:** no modelling changes; `hmm_v2.json` ships as merged. Small code changes only where shipping needs them (the default method, pinned dependencies, a script that prints the practice tables, a PDF export). Every number in the shipped text is printed by a committed script from committed `results/`, and a test keeps the text and the script in step.

**Tech Stack:** Python 3.11, numpy, pandas, pytest; pandoc 3.7 plus Microsoft Edge (headless) for the PDF.

**Spec:** `docs/superpowers/specs/2026-11-12-plan-4-ship-design.md`

## Review Focus

1. A stranger follows the README on a fresh machine: the one command must write the file with the reference sha256 (Task 5 proves it on a fresh clone).
2. A teammate edits the authors block and reruns the export: the command must rebuild the PDF from any working directory and fail loudly if pandoc or Edge is missing (Task 4 tests).
3. Shipped numbers drift from `results/`: the results page and the document must match what the script prints (Task 2 and Task 4 tests).
4. Em or en dashes, or a missing organiser heading, slip into the shipped text (Task 3 and Task 4 tests).
5. A new file built from our match gets committed (`docs/` CSVs, a PDF of outputs): the repo safety test must still catch data-like files (Task 1 extends it).
